## 亲手验收

1. 打开前端网址，看到 12 个地点与道路关系示意图。
2. 搜索“图书馆”或 lib，列表只显示 Library。中文名称是前端展示别名，不是已核验的校园地点名。
3. 点击地点列表或图上的地点标签，查看详情，点击“设为起点”或“设为终点”。
4. 默认北门到食堂点击“规划最短路线”，结果为北门 → 图书馆 → 学生活动中心 → 食堂，共 290 米。
5. 图中对应路段和地点变绿。每段距离和总距离都来自后端，不根据示意图线段长度计算。
6. 改起终点后，旧路线会清除；重新规划后显示新结果。交换起终点可反向查询。
7. 相同起终点会显示“你已在目的地”，距离为 0 米。

加载中会显示提示；接口失败时显示错误，首次加载失败可点“重新加载”。搜索无结果时显示空列表提示。

## 如何启动

先确保 MySQL999 正在运行，本地 .env 已配置。在 PyCharm 打开两个终端，工作目录均从项目根目录开始。

后端终端：

```powershell
.\.venv\Scripts\python.exe -m uvicorn backend.app.main:app --reload --host 127.0.0.1 --port 8000
```

前端终端：

```powershell
cd frontend
npm run dev
```

两个终端保持运行，Ctrl+C 停止对应服务。本次已经启动，不要重复启动占用同一端口。
在新电脑恢复前端时，先在 frontend 目录运行 npm ci，按照 package-lock.json 安装已锁定依赖。

## 点击规划之后发生什么

按钮调用 App.vue 的 plan 函数，api.ts 发送 /api/routes/shortest?start=0&end=6。
前端服务通过 Vite 的 /api 代理转交给 8000 端口的 FastAPI；后端从 MySQL 查询道路，计算路线，返回 JSON。
Vue 将结果存入 route，页面和 Leaflet 图层随之更新。改变起终点后，旧请求即使稍晚完成，也不会覆盖新选择。

数据库密码保留在项目根目录 .env，前端不读取它。前端只调用 API。
开发代理只在 npm run dev 时生效；未来公开部署需由 Web 服务器把 /api 转发给 FastAPI，直接上传 dist 不会继续提供开发代理。

## 为什么暂时是示意图

原始数据没有真实经纬度。这里使用 Leaflet 的平面坐标模式 CRS.Simple，单独保存人工排布的坐标，不修改数据库中的 null 经纬度。
没有加载真实地图瓦片或定位，不把道路连线视为真实可步行形状。中文别名和分类也只用于课程演示。
后续用核验后的地理坐标与道路折线替换布局时，需要单独实现地理地图模式，不能把当前示意坐标当作经纬度。
