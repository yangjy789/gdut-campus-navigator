| algorithm | 本次使用 dijkstra |
| start_id / end_id | 本次查询的起终点编号 |
| distance_m | 全程距离，单位米 |
| path | 按行走顺序排列的地点详情 |

## 三个代码层次

- routing.py：纯 Python 算法，只接收节点、边和起终点，不知道 FastAPI 或 MySQL。
- route_service.py：读取数据库中的地点与道路，把它们交给算法，组装地点详情与路段。
- main.py：接收 start、end 参数，返回 JSON，并将“编号不存在”“无路可达”等情况转换成 HTTP 错误。

同样一套算法以后可被普通路线接口和 AI 工具调用复用。

## Dijkstra 怎样工作

先将道路转换为邻接表：每个节点只记录与它直接相连的邻居和距离。双向道路加入两个方向；单向道路只加入声明的方向。

distances 保存目前发现的最短距离；previous 保存前一个地点和经过的道路，用来最后还原路线；queue 是按距离排序的候选队列。

以从 0 出发为例：起点距离是 0。取出它后，发现 Library 为 120 米、Administration 为 160 米、LakeGarden 为 180 米。
优先处理目前最近的 Library，再发现 StudentCenter 可以在 230 米到达；继续逐步更新，最终 DiningHall 可以在 290 米到达。
若发现同一地点的新路线更短，就更新距离、记录前驱并放入队列；队列中较旧的较长候选会被跳过。
当终点作为有效的最短候选被取出时，可以结束搜索。再沿 previous 反向找到起点，最后把顺序翻转。

Python heapq 每次弹出最小候选，不需要像原 C 代码那样每轮扫描所有节点。正权道路下，算法适用于这里的最短距离问题；算法入口也会拒绝零或负距离及无效端点。
用“缺少距离记录”表示尚不可达，不再依赖原 C 中的 INF=999999，所以超过这个值的合法路线也可以计算。
等长路线可能不止一条，接口返回其中一条，不承诺最少经过地点或输出全部等长路线。
