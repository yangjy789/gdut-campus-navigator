## 先理解原 C 代码

Place 保存地点代码、名称和介绍；CampusGraph 把地点和道路放在一起。
edge[a][b] 表示 a 到 b 的距离。对角线是 0，INF 表示没有直达道路。
AddRoad 同时设置 edge[a][b] 和 edge[b][a]，所以所有道路都是双向。
InitCampus 负责写入初始地点和道路，退出后修改不会保存。

ShortestPath 使用 Dijkstra：dist 保存当前最短距离，pre 保存路径前驱，used 标记已确定最短距离的点。
每轮选择尚未确定且距离最小的点，再尝试通过它缩短到相邻点的距离。
PrintPath 沿 pre 反向找回路径，再倒序打印。后续 Python 版本将使用邻接表和优先队列。

DFSPaths 则递归探索所有不重复经过节点的路径，通过 visited 避免环，回溯时取消访问标记。
MAX_PATHS=30 限制输出数量，因此菜单中的“所有简单路径”实际最多输出 30 条。

## 本阶段新增代码

prepare_demo.py 分为 extract、validate、main 三部分。
extract 只识别当前 C 文件的数组和 AddRoad 初始化格式，不是通用 C 语言解析器；修改 C 格式后需复核。
validate 先验证地点，再验证道路，最后从一个地点遍历所有邻居，确认能到达全部地点。
main 读取源码，执行提取与验证，保存 JSON 和报告。脚本未实现新的路线算法，也没有替代原 C 项目。

## 数据如何迁移

课程示例的名称和距离原样保留，坐标一律 null，标记 demo_only。
以 code=LIB 的地点为例：id=1 是内部编号，name=Library 是示例名称，description 是原有介绍。
road 中 start_id=0、end_id=1、distance_m=120 的意思是示例图中这两个点之间有一条长度为 120 米的边。
它不证明广工北门到图书馆实际相距 120 米。

## 已发现的问题

1. 原 C 输入清理循环遇到 EOF 可能一直循环；本次只归档，没有修改旧程序。
2. ChangeRoad 未限制距离小于 INF，输入过大时会与“无道路”哨兵含义冲突。
3. 原文件包含姓名、学号和班级，legacy 默认排除在 Git 之外，公开版本以后另行整理。
4. 真实校园图需要道路交叉点和建筑入口，不能简单连接建筑中心，否则可能穿楼。
