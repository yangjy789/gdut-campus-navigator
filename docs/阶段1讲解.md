# 阶段 1：让地点数据通过后端接口提供服务

## 本次完成

使用项目独立的 Python 3.13 环境，安装 FastAPI 和 Uvicorn。
实现健康检查、地点列表、按名称或代码搜索、地点详情，并生成交互式接口文档。
课程示例数据在服务启动时从 JSON 读取，尚未连接数据库。

## 在 PyCharm 使用

打开项目根文件夹，将解释器设置为本项目的 .venv\Scripts\python.exe。
可在“设置 → 项目 → Python 解释器”选择已有的本地环境。

终端工作目录应是项目根目录，运行下面的命令。显式使用项目解释器，不依赖终端是否激活环境：

```powershell
.\.venv\Scripts\python.exe -m uvicorn backend.app.main:app --reload --host 127.0.0.1 --port 8000
```

终端保持运行；Ctrl+C 停止。--reload 会在修改代码后自动重启，适合开发。
如果 8000 端口已在使用，先使用现有服务；需要另外启动时可将端口改为 8001，并对应修改访问地址。

也可在 PyCharm 添加 Python 运行配置：模块名称 uvicorn，参数 backend.app.main:app --reload --host 127.0.0.1 --port 8000，工作目录为项目根目录。

## 亲手验收

1. 打开 http://127.0.0.1:8000/api/health，看到 status=ok、place_count=12。
2. 打开 http://127.0.0.1:8000/docs，展开 GET /api/places，点击 Try it out。
3. keyword 输入 lib，点击 Execute，结果应只有 Library。
4. GET /api/places/{place_id} 输入 1，返回 Library；输入 999，返回 404。
5. 输入负数或字母编号，返回 422，表示请求参数不符合要求。

当前接口为英文课程示例数据，因此输入“图书馆”不会匹配 Library；后续接入真实中文数据再提供中文查询。

## 代码如何工作

浏览器发送 HTTP 请求 → main.py 中对应的函数接收请求 → 从已载入的地点中查询 → 按 schemas.py 定义的数据结构返回 JSON。

- main.py：接口入口。@app.get 表示“这个网址收到 GET 请求时调用下面的函数”。lifespan 在应用启动时读取数据，数据文件损坏会直接报错，便于发现问题。
- repository.py：负责从文件取数据，用相对于源码的绝对位置定位 JSON，不依赖启动目录。下一阶段可以把数据来源替换成 MySQL。
- schemas.py：定义一个地点有哪些字段及其类型，避免漏字段、坐标越界等错误，也提供接口文档中的结构说明。
- test_api.py：自动发送请求，检查真实响应是否符合预期。

例如访问 /api/places/1，1 就是路径参数 place_id；访问 /api/places?keyword=lib，lib 就是查询参数 keyword。
列表返回 total 和 items：total 是筛选后的地点数，items 是具体数据。空搜索返回全部，未匹配返回空列表。
详情找不到返回 404，而不是伪造一个地点。

```powershell
.\.venv\Scripts\python.exe -m pip check
```

requirements-lock.txt 保存了本次完整的安装版本，重建环境可安装该文件。

## 范围与下一步

此服务目前只绑定本机 127.0.0.1，不是公网网址；/docs 是接口调试页，Vue 用户界面在阶段 4 开发。
没有管理员、数据库、路线算法 API 或 AI 服务。本阶段不需要填写任何 API 密钥。
真实数据仍待核验，因此所有接口都使用 course_demo / demo_only 标记，不能提供真实校园导航。

下一阶段接入 MySQL，学习“请求 → 后端 → 数据库 → JSON”的完整查询过程。
