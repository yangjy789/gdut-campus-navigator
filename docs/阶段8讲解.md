## 架构

浏览器 → 前端容器（nginx，80 端口）→ /api 反向代理 → 后端容器（uvicorn，8000）→ 数据库容器（MySQL 8.0）。浏览器只访问同源地址，不存在跨域问题。

| 容器 | 镜像 | 职责 |
| --- | --- | --- |
| db | mysql:8.0 | 业务数据，healthcheck 等待就绪，数据卷持久化 |
| backend | 本机构建（python:3.13-slim） | FastAPI + 自动初始化 + 问答/工具调用 |
| frontend | 本机构建（node 构建 + nginx 托管） | 静态页面 + /api 反代 + 单页路由回退 |

两个命名卷：db-data 保存数据库文件，runtime-data 保存 .runtime（Chroma 索引与管理员凭据）。容器重建不会丢数据。

## 密钥与配置（安全要点）

- 镜像里**不含** .env、不含密钥：.dockerignore 排除了 .env 与 .env.*。
- 数据库密码、硅基流动 Key 由部署机环境变量注入（compose 的 `${VAR}` 引用）。
- 复制 `.env.deploy.example` 为部署机上的 `.env.deploy`，填入真实密码与 Key，用 `--env-file` 传入：
  ```
  docker compose --env-file .env.deploy up -d --build
  ```
- 生产上线前把 `COOKIE_SECURE=true`，并把 `ADMIN_ALLOWED_ORIGINS` 改成实际域名，否则管理员登录会被浏览器拒绝或来源校验拦截。
- 后端 8000 端口在 compose 里只绑定 127.0.0.1 供调试；正式部署可删除该 ports 映射，只暴露前端。

## 部署步骤（在装有 Docker 的机器上）

1. 安装 Docker Desktop（Windows/Mac）或 Docker Engine + Compose 插件（Linux）。
2. 在项目根目录执行 `cp .env.deploy.example .env.deploy`，编辑填入 DB_ROOT_PASSWORD、DB_PASSWORD、SILICONFLOW_API_KEY、域名等。
3. 构建并启动：
   ```
   docker compose --env-file .env.deploy up -d --build
   ```
4. 查看后端初始化日志，确认出现「启动服务」字样：
   ```
   docker compose logs -f backend
   ```
5. 浏览器打开 http://服务器IP:8080/ ，验证地点搜索、路线规划、知识问答、AI 规划路线。
6. 管理员密码在后端容器的 /app/.runtime/admin-credentials.txt：
   ```
   docker compose exec backend cat .runtime/admin-credentials.txt
   ```
7. 验收命令：
   ```
   docker compose ps
   docker compose exec backend python -m pytest backend/tests -q
   ```

## 自动初始化的幂等性

2026-11-23 修复：迁移 0003 新增 data_imports，记录 course_demo_v1 初始化状态。已有数据或管理员的旧库迁移时标记为已初始化；以后启动不补回已删除的地点和道路，即使管理员清空所有示例地点也不会重新导入。新空库的首次示例导入与标记在同一事务提交。不要通过删除该标记重置业务库。

entrypoint 依次等待数据库就绪 → 建库 → alembic 迁移 → 导入课程示例（已存在的 ID 不覆盖）→ 创建管理员（已存在不重置密码）→ 启动 uvicorn。重复执行 `up` 不会重复导数据或改密码。数据库就绪等待最多 120 秒。

## 云服务器与 HTTPS

- 云服务器需开放 80（HTTP）；上 HTTPS 建议在前置一层 Nginx/Caddy 或用云负载均衡做 TLS 终止，把 443 反向代理到本项目的 8080，并设置 `COOKIE_SECURE=true`。
- 域名确定后同步更新 `ADMIN_ALLOWED_ORIGINS`，用 https:// 开头。
- 备份：定期备份 db-data 卷（数据库）与 runtime-data 卷（管理员凭据、Chroma 索引）。
   ```
   docker run --rm -v gdut_campus_db-data:/data -v $(pwd):/backup alpine tar czf /backup/db-backup.tgz -C /data .
   ```
  （卷名以 `docker compose ps` 显示的项目名为准。）
- 课程示例数据不能用于真实导航：部署公开访问前仍需完成阶段 0 的真实坐标与道路核验。

## 已知限制与排障

- 本机实测已通过；仍需部署到云服务器并配置 HTTPS 才能实现「公开网址可访问」这一最终目标。
- Windows + Docker Desktop 4.99 首次安装异常时可能遗留 `sailor-ingest.sock` 重解析点，导致启动时报 `Access is denied`。以管理员身份运行 `scripts/docker_fix_windows.ps1` 可清理并重启（该脚本夺权强删 socket、配置国内镜像源）。
- 国内直连 Docker Hub 会超时：基础镜像需经国内源拉取后打官方 tag；Dockerfile 已内置清华 pip 源与淘宝 npm 源，可用 `PIP_INDEX_URL` / `NPM_REGISTRY` 构建参数覆盖。
- 宿主机 8000 端口被本地 uvicorn 占用时，backend 容器端口映射会失败；启动容器前先停止占用 8000 的进程。
- 限速按客户端 IP 统计，前置反向代理后所有请求源 IP 可能相同；生产多实例需改用共享的 Redis 限速。
- MySQL root 密码通过环境变量传给 healthcheck，会出现在容器 inspect 信息中；正式环境建议改用 Docker secrets。
- 前端容器以只读静态文件运行，管理员改地点/道路通过后端 API，刷新用户端即可见。

## 文件分工

| 文件 | 作用 |
| --- | --- |
| docker-compose.yml | 三容器编排、卷、网络、健康检查、环境变量注入 |
| backend/Dockerfile | 后端镜像，非 root 运行，entrypoint 自动初始化 |
| scripts/docker-entrypoint.sh | 等待数据库、建库、迁移、导数据、建管理员、启动服务 |
| frontend/Dockerfile | 多阶段构建：Node 编译 + nginx 托管 |
| frontend/nginx.conf | 静态路由回退与 /api 反向代理 |
| .dockerignore | 排除 .env、密钥、缓存、虚拟环境 |
| .env.deploy.example | 部署环境变量模板，不含真实密钥 |
