# 真实数据替换计划

安排：本次问题修复验收后，作为阶段 7.5 执行，放在阶段 8 的云服务器正式发布之前。本机 Docker 可继续用于开发与验证。此前阶段 0 的真实数据准备工作在这里补齐。

## 第一步：小范围采集

先选择一个入口到图书馆或教学楼的小区域，收集约 5～10 个地点及它们之间实际连通的步行道路。具体地点与通行信息需要来源或现场核验，不能把当前示例名称、位置和距离视为真实数据。

地点记录入口坐标、坐标系、名称、类别、资料来源和核验日期；道路记录路口/入口节点、折线、实际步行距离、方向、是否可通行及核验日期。入口和交叉路口才是道路连接点，不用建筑中心连直线代替实际道路。采集字段与规则见 data/real/collection-plan.json。

## 第二步：改造示例专用的数据结构

当前数据库及接口的 verification_status 只允许 demo_only，dataset_type 固定 course_demo，地图使用 Leaflet CRS.Simple 人工示意坐标。因此不能只替换 JSON 或在后台填经纬度就宣称已切换真实导航。

需要单独完成：真实/示例数据集隔离；核验状态与来源字段；统一坐标体系；真实道路折线与通行限制；独立真实数据导入及校验；地点别名随数据管理。保留示例库用于测试，先备份再切换业务库，不在已有库上直接覆盖。

## 第三步：地图与知识库一起切换

地图改用统一坐标体系的真实底图和道路折线，确认底图许可与署名；删除当前人工布局对真实数据的依赖。知识库补入已核验的校园事实，保留来源和日期，移除会把示例地点/距离解释成真实事实的内容。未知开放时间等信息继续明确标注未知。

## 第四步：现场验收后再扩大范围

对选定区域逐段验证道路连接、实际可步行性、距离与方向；测试绕路、不可达、起终点相同、地点歧义及 AI 与普通表单结果一致性。全部通过后才能给这部分数据标记已核验。然后逐步扩展到整个校区，不能用少量路线通过代表全校已核验。

## 第五步：继续阶段 8

Git 版本管理 → 云服务器部署 → HTTPS → 外网功能与备份恢复验收。若提前发布课设演示，必须继续清楚标注示例数据；对外提供真实导航以前，应先完成上述真实数据验收。

当前状态（2026-11-23 更新）：已接入官网 2026 地图与 51 条地点资料，详见阶段7.5讲解.md。首页默认官网资料模式，课设算路单独保留。真实经纬度与可计算路网仍缺失，尚未达到真实导航验收要求；不再要求用户自行采集，后续优先寻找许可允许的在线地理数据。
